Duckshell RepositoryDuckshell Repository

Duckshell Repo 是一个开源的插件分发服务器，提供高质量的 DLL 和 SO 文件供开发者和用户下载使用。支持 Windows、Linux 等多个平台。

Duckshell Repo is an open-source plugin distribution server providing high-quality DLL and SO files for developers and users to download and use. Supports multiple platforms including Windows and Linux.

使用本仓库Using This Repository

在 Duckshell 中添加本仓库很简单，只需在命令行执行以下命令：

Adding this repository to Duckshell is simple, just run the following command:

plugins repo dsrepo.lucheshidi.dpdns.org

执行后，Duckshell 会从本仓库中添加插件源。您就可以通过 Duckshell 的插件管理器浏览和安装本仓库中的插件。

After execution, Duckshell will add the plugin source from this repository. You can then browse and install plugins from this repository through Duckshell's plugin manager.

前置要求

Prerequisites

请确保你的服务器满足一下要求：

Please make sure your server meets the following requirements:

  • 系统：Linux 6或更新版本，Windows Server 7或更新版本
  • System: Linux 6 or newer. Windows Server 7 or newer.
  • 存储空间：至少 10GB 可用空间
  • Storage: At least 10GB of free space
  • 网络：稳定的互联网连接
  • Network: Stable internet connection
  • 权限：管理员或 root 权限
  • Permissions: Administrator or root access
  • 软件：安装Apache2，或Nginx
  • Software: Apache2 or Nginx installed

构建步骤

Build Steps

第一步：准备

Step 1: Preparation

创建以下目录结构：

Create the following directory structure:

  • /path/to/your/root/duckshell-repo/ - 主目录
  • /path/to/your/root/duckshell-repo/ - Main directory
  • /path/to/your/root/duckshell-repo/packages/ - 插件文件目录
  • /path/to/your/root/duckshell-repo/packages/ - Plugin files directory
  • /path/to/your/root/duckshell-repo/metadata/ - 元数据目录
  • /path/to/your/root/duckshell-repo/metadata/ - Metadata directory
  • /path/to/your/root/duckshell-repo/static/ - 主介绍目录，可放置index.html
  • /path/to/your/root/duckshell-repo/static/ - Main introduction directory, can contain index.html

请将/path/to/your/root/duckshell-repo/替换为你的镜像根目录

Please replace /path/to/your/root/duckshell-repo/ with your mirror root directory

第二步：构建

Step 2: Build

创建以下文件：

Create the following files:

  • /path/to/your/root/duckshell-repo/index.html - 用于浏览器访问跳转
  • /path/to/your/root/duckshell-repo/index.html - Used for browser access redirection
  • /path/to/your/root/duckshell-repo/static/index.html - 主要readme文件
  • /path/to/your/root/duckshell-repo/static/index.html - Main readme file
  • /path/to/your/root/duckshell-repo/metadata/index.html - 元数据索引文件
  • /path/to/your/root/duckshell-repo/metadata/index.html - Metadata index file

请将/path/to/your/root/duckshell-repo/替换为你的镜像根目录

Please replace /path/to/your/root/duckshell-repo/ with your mirror root directory

你可能也想要将别的镜像站的插件放入你的镜像站，Duckshell本身不负责由于版权原因而引起的纠纷。请将插件全部放入packages/

You may want to place other plugins from other mirrors into your mirror. Duckshell itself does not take responsibility for disputes arising from copyright reasons. Please place all plugin files into the packages/ directory.

重要！请确保你的服务器拥有一个公网IP或者一个稳定的域名，并且配置了HTTPS服务！

Important! Please ensure your server has a public IP or a stable domain and HTTPS configured!

第三步：验证

Step 3: Verification

请使用浏览器访问以下链接以确保你的镜像可用：

Please use your browser to access the following links to ensure your mirror is available:

  1. https://yourdomain.com/metadata
  2. https://yourdomain.com/metadata/index.html
  3. https://yourdomain.com/static/index.html
  4. https://yourdomain.com/static/
  5. https://yourdomain.com/plugins
  6. https://yourdomain.com/

请将yourdomain.com替换为你的服务器域名或IP地址

Please replace yourdomain.com with your server domain or IP address

第1到第4条链接需要返回一个HTML页面，第5条需要返回503或者一个含有文件夹的列表(如果你启用了Nginx的autoindex或者Apache的autoindexing)，第6条需要跳转到/static/

Links 1 to 4 should return an HTML page, link 5 should return a 503 or a directory listing (if you have enabled Nginx autoindex or Apache autoindexing), and link 6 should redirect to /static/

常见问题

FAQ

Q: 如何确保我的镜像站点正确配置？

Q: How do I ensure my mirror is configured correctly?

A: 请按照第三步（验证）中的步骤逐一检查所有链接。确保每个链接都返回正确的内容。您也可以查看浏览器的开发者工具（F12）来检查是否有任何HTTP错误。

A: Please follow the steps in Step 3 (Verification) to check all links one by one. Make sure each link returns the correct content. You can also use the browser's developer tools (F12) to check for any HTTP errors.

Q: 为什么我的HTTPS配置很重要？

Q: Why is HTTPS configuration important?

A: HTTPS确保了数据传输的安全性，防止中间人攻击。Duckshell 客户端需要安全的连接来下载插件。没有HTTPS，您的镜像站点可能会被安全检查拦截。

A: HTTPS ensures the security of data transmission and prevents man-in-the-middle attacks. Duckshell clients need a secure connection to download plugins. Without HTTPS, your mirror may be blocked by security checks.

Q: 我可以从其他镜像复制插件吗？

Q: Can I copy plugins from other mirrors?

A: 您可以从其他合法来源复制插件，但请确保您拥有必要的权限或许可证。Duckshell 对因版权原因引起的纠纷不负责。请将所有插件文件放入 packages/ 目录。

A: You may copy plugins from other legitimate sources, but ensure you have the necessary permissions or licenses. Duckshell is not responsible for disputes arising from copyright issues. Please place all plugin files in the packages/ directory.

Q: 我的域名或IP地址可以改变吗？

Q: Can my domain or IP address change?

A: 不推荐。如果您的域名或IP地址发生改变，所有使用您镜像的客户端都需要更新配置。建议使用稳定的域名和静态IP地址，或者使用DNS解析来处理IP变化。

A: Not recommended. If your domain or IP address changes, all clients using your mirror will need to update their configuration. It's recommended to use a stable domain and static IP address, or use DNS resolution to handle IP changes.

Q: metadata 和 packages 目录有什么区别？

Q: What is the difference between the metadata and packages directories?

A: metadata/ 目录用于存储关于插件的索引和信息文件（如 index.html），而 packages/ 目录存储实际的插件文件（DLL、SO等）。两者都是必需的。

A: The metadata/ directory stores index and information files about plugins (such as index.html), while the packages/ directory stores the actual plugin files (DLL, SO, etc.). Both are required.

Q: 如果我的镜像无法访问怎么办？

Q: What should I do if my mirror is inaccessible?

A: 首先检查您的web服务器（Apache2或Nginx）是否正在运行。然后验证防火墙设置是否允许HTTP/HTTPS流量。最后，检查您的服务器是否有足够的网络带宽和存储空间。

A: First, check if your web server (Apache2 or Nginx) is running. Then verify that your firewall settings allow HTTP/HTTPS traffic. Finally, check if your server has sufficient network bandwidth and storage space.

Q: 我需要定期维护我的镜像吗？

Q: Do I need to maintain my mirror regularly?

A: 是的，建议定期检查以下内容：（1）服务器的可用存储空间；（2）web服务器日志中的错误；（3）更新和添加新的插件版本；（4）检查SSL证书的过期时间。建议每月至少检查一次。

A: Yes, it is recommended to regularly check the following: (1) Available storage space on your server; (2) Errors in web server logs; (3) Update and add new plugin versions; (4) Check the expiration date of SSL certificates. Check at least once per month.

Q: 如何处理旧版本的插件？

Q: How should I handle old versions of plugins?

A: 您可以在 packages/ 目录中为不同版本创建子目录（例如 v1.0/、v2.0/）来组织插件。在元数据中指定版本信息，允许用户选择下载特定版本。也可以存档旧版本以节省存储空间。

A: You can create subdirectories in the packages/ directory for different versions (e.g., v1.0/, v2.0/) to organize plugins. Specify version information in the metadata to allow users to select specific versions for download. You can also archive old versions to save storage space.

Q: 我可以限制对我镜像的访问吗？

Q: Can I restrict access to my mirror?

A: 可以。您可以在web服务器配置中使用身份验证（如HTTP基本认证）、IP白名单或API密钥来限制访问。在Apache2中可以使用 .htaccess 文件，在Nginx中可以使用 auth_basic 模块。

A: Yes. You can restrict access using authentication (such as HTTP basic authentication), IP whitelists, or API keys in your web server configuration. In Apache2, you can use .htaccess files, and in Nginx, you can use the auth_basic module.

Q: 我应该如何处理下载统计和日志？

Q: How should I handle download statistics and logs?

A: web服务器会自动在日志文件中记录所有请求。对于Apache2，日志通常在 /var/log/apache2/ 目录；对于Nginx，日志在 /var/log/nginx/ 目录。您可以使用日志分析工具（如ELK Stack或Goaccess）来分析下载统计和用户行为。

A: Your web server automatically logs all requests in log files. For Apache2, logs are typically in the /var/log/apache2/ directory; for Nginx, logs are in /var/log/nginx/. You can use log analysis tools (such as ELK Stack or Goaccess) to analyze download statistics and user behavior.
